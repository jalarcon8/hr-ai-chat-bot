# Quantic Requirements Traceability

Source: [Quantic AI Agent project](quantic-project-requirements.pdf). Page numbers refer to
the eight-page PDF. Wording such as "should", "where feasible", "approximately", and
"optional" retains the source's level of obligation; project constitution requirements can
be stricter. Ownership identifies one primary feature and, where useful, supporting features.
Statuses reflect recorded verification where updated; other features retain their own
checkpoint status. The Milestone 4 review updates all **33 F006-assigned rows** (QR-003-007
and QR-033-060). "Verified (documentation)" does not imply live acceptance.
"Unmet" and "Partially Verified" preserve missing required evidence; "Not Applicable"
is used only for the conditional separate-MCP deployment requirement.

## Coverage and qualification notes

- All ten numbered technical sections and the substantive overview, project description, and
  submission requirements have assigned owners. Rows may combine closely related bullets;
  the authoritative PDF remains the source for full context.
- The PDF's five-tool minimum is QR-024; this project's six named tools are a proposed
  feature choice, not a separate Quantic minimum.
- The rubric on pp. 7-8 describes grading levels rather than additional mandatory scope.
  Optional extra services, exact-match metrics, and retrieval enhancements are not mandatory.
- The source permits mock actions or confirmation; the constitution is stricter for
  state-changing operations: synthetic data only, explicit confirmation, and reversible/resettable.
- F004 is conditionally complete, not fully accepted: the latest local full suite passed
  476 tests with 5 opt-in live tests skipped, and repository-wide Ruff passed. Hosted
  Ubuntu/Windows CI and live PTO and remote-work acceptance remain unverified. See
  [F004 tasks](../../specs/004-hr-agentic-workflows/tasks.md) for the recorded evidence,
  failure history, and open T021.
- F005 local verification: full pytest passed with 488 passed, 5 skipped, and no failures;
  repository-wide Ruff passed. QR-032 remains partially verified because the UI prompt
  dispatch and F004 back-end workflows were tested separately, not as one F005-to-stdio
  integration run. The active CI workflow had no hosted run for branch `005-chat-interface`;
  hosted CI is unverified and remains with F006. The live provider returned
  `llm_request_failed` during the earlier browser checkpoint and was not retried.
- F006 owns final delivery while earlier features own their component behavior. A
  **Not Started** owner status does not negate supporting artifacts from an earlier feature.
- The F004/F005 hosted-CI statements above describe historical checkpoints, superseded for
  CI only by F006's passing Windows/Ubuntu code-baseline jobs. They are not upgraded into
  successful live F004 workflow acceptance. [Final report](../../evaluation/final-report.md)
  records 527 local passes and five explicit live skips, not 532 successful live checks.
- F006 closure was authorized despite incomplete Milestone 3. Subsequent offline review
  partially addresses QR-041; one [bounded continuation](../../evaluation/completion-plan.md)
  is authorized after protected-main CI/merge. QR-043 remains unmet, QR-042/057/058 partial,
  and QR-048-051/055/059 retain
  recording/access/submission/participant gaps. Final documentation/evidence changes still
  require protected-main review and their own ordinary CI. No requirement was waived.
